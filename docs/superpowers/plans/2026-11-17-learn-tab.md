# Learn tab — implementation plan

Spec: `docs/superpowers/specs/2026-11-17-learn-tab-design.md` (draft; this plan is valid only
once the owner approves that spec). Branch: `learn-tab` from `main` at 0.1.11.

Detail level: phase 1 is specified task by task. Phases 2 and 3 list tasks, files and
interfaces; their test code is written when the phase starts, because it depends on the
word-list format confirmed in task 2.1. Phases 4 and 5 are out of scope here.

## Global constraints

- No new Gradle dependency. Word lists are plain assets.
- TDD for every task: failing test first, for the right reason; then code; then commit.
- CI before each commit: `./gradlew :core:model:test :core:data:testDebugUnitTest :reader:testDebugUnitTest :app:testDebugUnitTest :app:lintDebug`. No new lint warnings.
- Every string in `values/` and `values-vi/`.
- Migrations are explicit and additive; each has a test that upgrades a populated database
  and compares the pre-existing rows.
- No network call is added in phases 1–3.

## Review focus

Migration safety, scheduler correctness at boundaries (first review, lapse, long intervals,
clock moving backwards), cloze fallback, and that review works with no key and no network.

## Phase 0 — backup covers learning data

Follow the approved October 29 backup/export plan. Add to its table list: `learning_answers`,
`vocabulary`, and after phase 1 `vocabulary_reviews`. No further planning here.

## Phase 1 — daily review (target 0.2.0, DB v11)

### Task 1.1 Scheduler (pure)
- Create `core/model/src/main/kotlin/dev/kent/windbook/core/model/ReviewScheduler.kt`
  ```kotlin
  enum class ReviewGrade { AGAIN, GOOD, EASY }
  data class ReviewState(val dueAt: Long, val intervalDays: Int, val ease: Float, val repetitions: Int, val lapses: Int)
  object ReviewScheduler {
      fun initial(now: Long): ReviewState
      fun next(state: ReviewState, grade: ReviewGrade, now: Long): ReviewState
  }
  ```
- Test `ReviewSchedulerTest`: new card is due now; GOOD gives 1 day then 3 then interval×ease;
  EASY grows faster than GOOD; AGAIN resets repetitions, adds a lapse, lowers ease but never
  below 1.3, and is due again within the session (10 minutes); interval is capped at 365 days;
  a `now` earlier than `dueAt` never produces a negative interval.

### Task 1.2 Cloze builder (pure)
- Create `core/model/.../ClozeBuilder.kt`: `fun cloze(quote: String, term: String): Cloze?`
  returning the sentence containing the term with the term replaced by a blank of fixed width,
  plus the answer as written in the book. Returns null when the term is absent.
- Test `ClozeBuilderTest`: case-insensitive match, whole-word only ("art" not in "start"),
  trailing punctuation kept, first occurrence blanked when repeated, multi-word terms,
  Vietnamese diacritics in the surrounding text untouched, null when absent.

### Task 1.3 Schema v10→v11
- `core/data/.../db/LearningDao.kt`: add `VocabularyReviewEntity` (`vocabulary_reviews`:
  `word_id` PK with FK to `vocabulary.id` ON DELETE CASCADE, `due_at`, `interval_days`, `ease`,
  `repetitions`, `lapses`, `last_reviewed_at` nullable) and DAO methods `dueWords(now, limit)`,
  `newWords(limit)`, `upsertReview`, `dueCount(now)` as `Flow<Int>`.
- `LearningMigration.kt`: explicit `MIGRATION_10_11` creating the table and index.
  `WindBookDatabase.kt`: version 11, register entity and migration.
- Tests: migration test with a populated v10 database (books, annotations, answers, words)
  asserting all prior rows are unchanged and the new table is empty; DAO test that deleting a
  word removes its review row and that words of soft-deleted books are excluded from due lists.

### Task 1.4 Repository
- `core/data/.../learning/ReviewRepository.kt`: `session(now): List<StudyCard>` (due first,
  then up to the daily new-word cap), `grade(wordId, grade, now)`, `dueCount(now): Flow<Int>`.
  `StudyCard` carries term, meaning, quote, book id, annotation id.
- Tests: ordering, the cap of 20 new words per local day, grading persists the scheduler result,
  a deleted word disappears from a running session without error.

### Task 1.5 Learn tab shell
- `navigation/Routes.kt`: `LearnKey`. `TopLevelTab.kt`: `LEARN` between NOTES and SETTINGS.
  `WindBookNavHost.kt`: entry. `WindBookTabBar.kt` and `ui/icons/WindBookIcons.kt`: icon.
- New `app/.../learning/LearnScreen.kt` + `LearnViewModel.kt`: Today card (due count, Start),
  Words list (reuses the rows of the current vocabulary dialog, with search).
- `NotesScreen.kt`: the vocabulary button navigates to Learn instead of opening the dialog.
- Strings: `tab_learn`, `learn_today`, `learn_due_count` (plural), `learn_start`,
  `learn_nothing_due`, `learn_words`, `learn_empty`.
- Tests: tab bar shows five tabs in order; empty state when no words; due count rendering in
  English and Vietnamese; Notes button navigates.

### Task 1.6 Review session screen
- New `app/.../learning/ReviewScreen.kt` + `ReviewViewModel.kt`: cloze front, reveal, three
  grade buttons, progress "3 / 12", "Open in book" using the existing `openReader(bookId,
  annotationId)`, summary at the end.
- Strings: `review_show_answer`, `review_again`, `review_good`, `review_easy`,
  `review_open_in_book`, `review_done_title`, `review_done_body`.
- Tests: fallback card when cloze is null; grading advances and persists; rotation keeps the
  current card and reveal state; finishing shows the summary and returns to Today.

### Task 1.7 Verification and release
- Emulator: add words through the AI card or seeded test data, run a full session, restart,
  change the device date forward and confirm due counts; large font in both languages.
- Upgrade check: install 0.1.11 with data, upgrade, compare row counts and hashes.
- Whole-branch independent review, one fix pass, then version 0.2.0, APK to `publish/`.
- Update `AGENTS.md` §4 (DB v11, new tab), §8, §9 and a new `docs/testing/learn-tab-checklist.md`.

## Phase 2 — levels (no schema change)

- 2.1 Confirm NGSL and NAWL licence text and file format; add files and attribution under
  `app/src/main/assets/wordlists/` and to the Open-source licences strings. **Stop and report
  if the licence is not CC BY-SA 4.0 or forbids bundling.**
- 2.2 `core/model/.../WordLevels.kt`: `enum class WordBand { B1K, B2K, B3K, ACADEMIC, BEYOND }`,
  `class WordLevels(headwords, inflections) { fun band(word: String): WordBand; fun headword(word: String): String }`.
  Pure, loaded from text. Tests with a tiny fixture list.
- 2.3 Loader in `:core:data` reading the assets once, off the main thread; memory measured on
  the emulator and recorded.
- 2.4 Words list: band chip per word, filter by band, counts per band on the Today card.
- 2.5 Settings: target band (default from the owner's answer to spec question 1).

## Phase 3 — suggestions while reading (DB v12)

- 3.1 `core/model/.../WordCandidates.kt`: tokenise text into sentences and words; return
  candidates (headword, sentence, offset) filtered by band, saved words and known words. Pure.
- 3.2 Migration v11→v12: rebuild `vocabulary` with nullable `answer_id` and new `book_id`,
  `quote`, `locator`; create `known_words(headword PK, created_at)`. Rows preserved; test as 1.3.
- 3.3 Chapter text source: EPUB first, through the existing Readium resource access; spike on
  PDF page text and record the result before promising it.
- 3.4 Reader overflow action "Words in this chapter" → bottom sheet with Add / I know this.
- 3.5 Words saved without a meaning show "Add meaning" (type it, or open the existing AI card).
- 3.6 Verification as 1.7, including a long chapter timing on the emulator.
